Korina Agent

Hackathon refactor preview · 22 October 2026. Work is being reviewed on codex/hackathon-refactor, based on alpha. These changes are not yet merged into alpha or the release branch. Setup and rehearsal guide · Progress and verification evidence · Review PR #24.

Korina Agent is the optional background reporting agent beside Korina Converse’s voice loop. It receives bounded transcript deliveries and produces state reports, injections, and permission questions. The current built-in agent does not execute tools or maintain durable tasks or memory.

Separate response and agent paths

The browser’s spoken response uses /api/chat and its response-provider settings. Background reporting has independent provider, model, endpoint, and credential settings. Reports enter the browser through the configured delivery and interruption policy; selecting a Python channel does not reroute browser voice.

AgentAdapter defines synchronous submit, polling, permission, reset, health, and capability operations. The optional legacy HTTP extension adds transcript prompt/injection envelopes. Read-only /api/agent/capabilities exposes protocol version 1 and the operations the selected adapter actually supports. An external agent needs a compatible adapter; Hermes remains a stub.

Recover an exhausted report budget

If a Meta/OpenAI-compatible model returns no visible report with finish_reason: "length", the built-in worker exposes an actionable last_error and agent_error event, retaining its previous report. Increase State report max tokens in Korina Agent settings deliberately, or choose another agent model, then submit another turn. Its separate default is 512; a manual adjustment such as 512 → 2048 can let the same worker recover without resetting the report. There is no automatic increase or retry. Intentional empty reports ending with stop remain suppressed; visible truncated reports are unchanged.

Session and channel ownership

The built-in Python channel admits a turn only while its worker is idle and captures the event cursor atomically. Busy work receives a definite rejection; legacy HTTP submissions keep their coalesced queue. Reset or agent off/on cancels an old wait. Duplicate completions retain their own report; lost event history requires explicit recovery instead of returning a later turn’s report. Custom adapters keep their own memory and cancellation contract.

Session reset or agent disable retires old deliveries and UI results. Failed permission acceptance preserves the pending question for retry; a failed backend reset keeps delivery and polling blocked until Clear Session succeeds. Owned connected HTTP closes stale I/O so the existing worker can recover, without claiming cancellation of remote model computation.

The Python ConverseChannel contract exposes send, stream, cancel, and optional health. An admitted send that times out, loses completion polling, or has its caller cancelled requires a successful explicit cancel() on its captured adapter before another send is admitted. A completed error report remains a normal completion. An adapter may use AgentAdmissionRejected only when it guarantees no work was admitted; definite disabled/stale built-in rejections can retry without resetting memory.

The browser Channel picker ignores stale discovery responses and disables selection while its explicit save is pending. A confirmed selection is persisted before it becomes active; save failure preserves the previous server selection and exposes a retryable diagnostic.
