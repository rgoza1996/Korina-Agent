Hackathon setup and rehearsal

Before rehearsal, review the observed speech-runtime evidence and agent protocol.

Hackathon refactor preview · 22 October 2026. Work is being reviewed on codex/hackathon-refactor, based on alpha. These changes are not yet merged into alpha or the release branch. Setup and rehearsal guide · Progress and verification evidence · Review PR #24.

Korina Converse brings microphone capture, transcription, a response model, speech playback, and background agent reports into one local voice interface. The refactor focuses on a predictable demo and simpler runtime code.

What the preview improves

Portable startup

A checkout serves its own browser assets. Provider binaries resolve through configuration and PATH. Installed wheels include the UI and keep generated state in the user’s data directory.

Shared transcription flow

Buffered, partial, and streaming transcription share capability-cache, no-speech, and fallback resolution. Conversion and inference run away from the async request loop; quiet or clipped Whisper fallback keeps VAD off.

Bounded background work

Agent deliveries have a concurrency limit, validated transcript sizes, and reset protection for stale results. Priority classification has its own testable rules.

Clear diagnostics

Health comes from server-resolved providers and endpoints. Transient polling failures, lazy model loading, and unavailable services have distinct states.

Start from a source checkout

The commands below target the preview branch. Python 3.10+ is required. Install FFmpeg separately for browser audio conversion. Node is only needed for frontend development checks.

git clone https://github.com/rgoza1996/Korina-Agent.git
cd Korina-Agent
git switch codex/hackathon-refactor
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[whisper]'
python -m korina.app

Open localhost:8001. The initial runtime settings are seeded from Korina/config/config.example.json. Choose an available response model and endpoint in Settings. Model weights and external provider servers are separate prerequisites.

For local speech output, use a second terminal in the source checkout with the same environment:

source .venv/bin/activate
python -m pip install 'torch>=2.4,<3' --index-url https://download.pytorch.org/whl/cpu
python -m pip install -e '.[tts]'
OMP_NUM_THREADS=4 python kokoro-streaming-server.py

Kokoro loads its pipeline on first speech and may download weights. Warm the selected voice before presenting. Its default port is 8880. An existing compatible endpoint can be configured instead.

On Linux with a systemd user session, ./Korina/install-services.sh validates and records checkout/interpreter paths. KORINA_PYTHON and optional KORINA_TTS_PYTHON select interpreters; invalid explicit overrides abort. Bundled services use ports 8001/8880; foreground bind variables do not reconfigure installed units. Startup reports missing units, failed starts, and failed TCP waits. Customized unit ports use --no-wait followed by the HTTP smoke against their actual URL. The local provider lifecycle remains Linux specific.

For CPU Linux, install the system espeak-ng package too. Warm the speech models before presenting; select a suitable Torch build for other devices.

Run a built wheel

From the preview checkout, build and install the package:

python -m pip install '.[dev]'
python -m build
python -m pip install dist/*.whl
korina

The wheel includes the browser UI, configuration example, and acknowledgement manifest. It keeps generated config and ACK audio under ${XDG_DATA_HOME:-~/.local/share}/korina. A source/editable install keeps that state beside Korina/. KORINA_APP_DIR selects a complete alternate runtime tree.

Speech engines are optional dependencies. The built wheel’s korina-tts command starts Kokoro after its TTS extra is installed. Building/installing the base package alone does not install a response LLM or preload speech models. See the README for the current install contract.

Before the demo

  1. Choose the intended response model and confirm its endpoint is running. Keep agent reporting off until basic voice round trips work.
  2. Preload the Whisper model and TTS voice on the demonstration machine so downloads do not interrupt the presentation.
  3. Run python scripts/check_stack.py and inspect /api/ready. Readiness returns 503 for a failed required check; /api/health remains HTTP 200 for backend liveness. A reachable lazy Kokoro counts as available, so warm actual speech before presenting.
  4. Use localhost or an HTTPS origin for microphone access. Allow microphone permission, speak one short turn, and verify the transcript, reply, and audible playback.
  5. Enable the background agent and deliver another turn. Confirm that a report appears in the debug panel and normal reports become context without an unnecessary interrupt.
  6. Test interruption, Clear Session, and one unavailable-provider case. Confirm the interface recovers and describes the affected provider accurately.
  7. Run the read-only smoke command, then rehearse actual chat, speech, interruption, and recovery on the prepared machine.
python scripts/check_stack.py --base http://127.0.0.1:8001
# Infrastructure-only check when models are intentionally unavailable:
python scripts/check_stack.py --base http://127.0.0.1:8001 --allow-degraded

The smoke command reads UI/assets, capabilities, health, and readiness. --allow-degraded accepts unavailable model services while checking the HTTP/assets layer; it does not establish a working voice demo.

Legacy regression runner retired. tests/regression_smoke.py prints replacement commands and exits 2 without runtime operations. Use scripts/check_stack.py for the read-only gate, current deterministic suites for software checks, and the rehearsal below for real model and hardware behavior.

Recovery to rehearse

  • Optional ACKs: Leave acknowledgement playback off unless needed. When enabled, confirm the selected voice has cached clips; a queued rebuild does not mean speech is ready. Voice settings are saved before rebuilding. Save/catalog/rebuild failures appear beside the ACK selector, separately from transcription status.
  • Malformed ACK catalog: Repair Ack/ack_phrases.json when the diagnostic requests it. Startup and required voice readiness stay available, health exposes unknown ACK counts, and ACK endpoints recover on the next request after repair. Invalid rebuilds preserve existing audio and queued work. See the catalog limits and recovery contract.
  • Suspended playback: Streaming speech completes against the browser audio clock. Queued audio remains owned while the AudioContext is suspended; Stop remains available. A closed context reports an error instead of claiming completion. Rehearse actual audible playback on the event machine.
  • Channel selection: Select a registered Python channel and confirm the saved active value. The picker rejects older discovery results and disables changes until a save is confirmed. Failed saves keep the previous server selection and permit a Channel-tab retry. Python channel selection does not reroute the browser’s /api/chat voice response.

Verification and remaining gaps

Event-specific Meta requirements have not been supplied. This preparation does not claim a particular Meta integration or hackathon eligibility.

Deterministic tests cover backend contracts, fallback behavior, request limits, background-worker concurrency, frontend health behavior, module imports, portable paths, and packaging. Local checks and final CI results are recorded in issue #23 and the code review.

  • Actual CPU Whisper and Kokoro inference and native browser capture/playback scheduling passed locally with a fake microphone. A separate pinned local SmolLM2 run also completed actual response/agent inference and next-response injection. The tiny model mostly echoed input. Physical audio devices, useful presentation response/agent models, GPU execution, and provider activation on the demonstration hardware still require rehearsal.
  • The agent currently produces reports and events. A complete tool-execution runtime, durable memory, and arbitrary third-party agent support remain separate roadmap work.
  • This preview has not been promoted to alpha or master. A passing unit suite does not establish end-to-end demo readiness.
