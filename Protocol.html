Agent protocol, version 1

Hackathon refactor preview · 22 October 2026. Work is being reviewed on codex/hackathon-refactor, based on alpha. These changes are not yet merged into alpha or the release branch. Setup and rehearsal guide · Progress and verification evidence · Review PR #24.

The implemented agent contract is documented in the complete versioned protocol, including copied requests, event examples, limits, cancellation, priority classification, sanitization, and migration.

Capability discovery

curl -s http://127.0.0.1:8001/api/agent/capabilities

This read-only endpoint returns protocol_version: 1, the selected adapter ID and declared capabilities, whether the optional legacy HTTP extension exists, and the HTTP operations the bridge exposes. It does not submit work, probe health, or call a model.

Separate interfaces

InterfacePurpose
AgentAdapterSynchronous Python submit, event polling, permission answer, reset, health, and capability contract
Optional legacy HTTP adapterFull transcript prompt/injection and legacy response dictionaries
ConverseChannelAsync Python send, stream, cancel, and optional health contract
Browser voice responseIndependent /api/chat response provider; selecting a Python channel does not reroute browser voice

A core adapter can support prompt delivery without implementing full transcript injection. Inspect operation discovery and handle HTTP 409 for unavailable extensions. Hermes remains a stub, and the built-in agent reports state and permission questions without executing tools.

Unsaved model discovery

GET /api/agent/models uses saved settings. Diagnostic POST /api/agent/models accepts bounded candidate provider/base/key and response fallback fields in its JSON body, without saving configuration or activating services. It keeps credentials out of URLs and validation diagnostics. An omitted direct agent key is inherited only for the same actual saved API URL; explicitly supplied keys and same-response-base fallback follow normal scope rules.

Delivery and session rules

  • Validate HTTP status and acceptance envelopes before treating a submission or reset as complete. Permission answers require accepted:true; failed confirmation preserves the pending question for retry.
  • Retain the authoritative event cursor returned by polling. A lower cursor indicates a new server session; discard old agent context.
  • The built-in ring retains at most 100 whole events and 4 MiB of UTF-8 JSON. The complete polling response also fits 4 MiB, including its snapshot; additive events_truncated/events_omitted fields describe response omissions. These fields do not count earlier ring eviction.
  • Input diagnostics record the exact prepared model context: at most 64 configured recent turns, 2000 characters per user/assistant turn, and the final 4000 characters of the previous report. Pending injections retain bounded serialized suffixes.
  • After reset or cancellation, discard old in-flight results. Owned background HTTP checks session ownership about every 50 ms and closes stale connected I/O, letting the same worker recover. Direct state-report requests retain their ordinary deadline; connection closure does not prove remote computation stops.
  • Transcript and permission admission retain their original built-in generation through configuration reads and dispatch. Reset or disable/re-enable rejects retired requests before publication or queueing; failed worker startup restores the previous status and allows retry.
  • The Agent enable checkbox has its own activity epoch and serialized non-coalescing control writes. Rapid off/on persists both transitions; failed disable stays ahead of enable until retry. Disable retires pending agent context, permissions, interruptions, and owned requests while ordinary chat and Live capture continue.
  • A successfully saved disable invalidates only built-in transient work. It never resets a custom adapter or durable memory. Re-enable baselines the selected event cursor before fresh delivery. A reply that already included a retired report is discarded; ordinary pending replies continue.
  • An admitted Python-channel send that times out, loses polling, or has its caller cancelled blocks further sends until explicit cancel() successfully resets its captured adapter. Completed error reports remain normal completions. Channel switching persists selection before publishing it; failed saves preserve the previous active channel.

For wire shapes, exact limits, priority rules, and integration examples, use the protocol source and /openapi.json.
