Observed runtime verification

Hackathon refactor preview · 22 October 2026. Work is being reviewed on codex/hackathon-refactor, based on alpha. These changes are not yet merged into alpha or the release branch. Setup and rehearsal guide · Progress and verification evidence · Review PR #24.

These are local observations from 22 October 2026. Exact versions, model revisions, timings, and later check totals are recorded in the repository verification record.

Real browser voice path

Chromium captured an espeak-ng WAV through its fake microphone using native MediaRecorder and VAD. Korina ran actual tiny.en Whisper CPU/int8 transcription, sent the transcript to a deterministic local response fixture, synthesized the reply with actual Kokoro af_heart on CPU, and scheduled nonzero PCM through native WebAudio. Playback reached its ended event; stopping live mode released capture. There were no page or console errors.

The small Whisper model made recognition errors. This smoke proves the runtime path, not transcription quality or presentation latency. The integration run also exposed duplicate current-turn delivery to the LLM; the refactor corrects the history contract and adds executable regressions.

The follow-up full-final path discarded redundant partial work instead of waiting for it to drain. One partial request completed and the next was aborted by the browser. A client abort does not prove backend inference was cancelled. The two recorded timings are single observations, not a controlled benchmark.

Actual speech services

  • Whisper buffered, partial, and SSE endpoints returned real transcripts using faster-whisper 1.2.1 with PyAV 18.1.0. A fresh PyAV 19 install failed decoding; the optional dependency now constrains PyAV below 19 and CI exercises a real WAV decoder without model weights.
  • Kokoro 0.9.4 with Torch 2.14.1+cpu produced valid mono WAV and SSE audio. Busy requests returned retryable HTTP 503 while health stayed available.
  • CPU synthesis was slower than the resulting speech duration. Warm models and measure the selected presentation hardware.

Agent and permission integration

Seven scenarios passed through actual Chromium modules, the real backend/agent worker, and a local deterministic model fixture: sanitized prompt delivery, exactly one next-response injection, permission answer/follow-up, reset while a model call was held, fresh-session recovery, and delayed-chat suppression. Reset took 72 milliseconds; agent model HTTP concurrency stayed at one. Speech in this check was a short silent PCM fixture, with no external model inference or tool execution.

Automated checks and remaining rehearsal

Checkpoint dd7f990 passed 484 Python tests with 87% coverage, 113 Node tests, 24 Chromium tests, and isolated wheel checks. Clean Python 3.10, 3.11, and 3.13 environments each passed 483 tests, skipping only the optional Whisper decoder exercised on Python 3.12. See testing and issue #23 for the updated totals after follow-up fixes. Hosted Actions jobs did not start because the account billing/spending limit blocked them.

Physical microphone/headset behavior, audible speakers, human interruption, the chosen real response/agent models, GPU execution, and event-specific Meta requirements still need rehearsal. Use the demo checklist. Pages source is maintained on gh-pages; live hosting is not configured.
