Korina Converse

The local-first, voice-first design chat channel. It owns the human-facing loop: microphone capture, VAD/endpointing, STT, response-LLM calls, TTS playback, barge-in, interrupts, and permission prompts. Converse is designed to be a channel that hosts any compatible agent.

Design principle: Korina is local-first — it is designed to keep your voice data and inference on your own hardware. However, it can fall back to cloud providers when your local hardware cannot fit the selected model. For example, running Qwen3-27B at Q8 (requires ~32GB VRAM) or GPT-OSS-120B at MXFP4 (requires ~64GB VRAM) is not realistic on typical consumer hardware.

Estimates based on faster-whisper base + Qwen3.5-0.5B as the lightweight STT + LLM baseline.

STT models: faster-whisper base.en (~74M params, ~150MB INT8) is the minimum. Larger models (medium.en ~418M, large-v3 ~1.5B) improve accuracy at the cost of VRAM/speed.

LLM models: Qwen3.5-0.5B Q8 (~1GB) is the minimum viable for basic conversational quality. Qwen3.5-4B Q8 (~4.5GB) is the practical floor for decent response quality. Larger models (7B, 13B+) dramatically improve output quality but require corresponding VRAM headroom.

Kokoro TTS: TTS runs on CPU (omnivoice is lightweight, ~100MB RAM). No discrete GPU needed for TTS.

Core Features

Live VAD

Browser-side adaptive energy voice activity detection with configurable endpointing thresholds: 3200ms silence for reading/dictation, 950ms for conversation mode.

Partial Transcription

Rolling partial transcription windows (~1.8s each) are queued rather than dropped, so slower STT inference catches up gracefully without losing audio.

Response LLM

Browser sends transcript to the configured OpenAI-compatible response LLM endpoint. Provider-agnostic: llama.cpp, LM Studio, Ollama, or any custom endpoint.

Kokoro TTS

Kokoro/OpenAI-compatible TTS with Web Audio SSE streaming. Voices selectable in the UI. Acknowledgement phrases generated and cached per voice on startup.

⏸️ Barge-in & Interrupts

Speak during playback to interrupt. Agent interrupts use a configurable cooldown (default 3000ms padding) to prevent recursive interruption.

Permission UX

Permission requests from the agent are spoken by Converse and answered through the agent permission endpoint. Converse is always the human-facing permission surface.

Converse Channel Protocol (Phase 5 Commit 1 — Shipped)

Converse talks to any agent implementation through a stable async protocol (ConverseChannel) rather than reaching into the agent service directly. The protocol layer lives in korina.converse and was added on top of the existing HTTP routes — chat/STT/TTS pipelines are unchanged.

ConverseChannel Protocol

Abstract base class with send(), stream(), cancel(), and health(). Adapters must implement name (a short id used by the registry) and the four async methods. The protocol is @runtime_checkable so isinstance(ch, ConverseChannel) works without explicit inheritance.

Thread-safe Registry

register_converse_channel(), unregister_converse_channel(), get_converse_channel(), set_active_converse_channel(), list_channels(), get_active_channel_name(). The active channel is process-global; reset_for_testing() clears it.

KorinaConverseChannel (default)

Bridges the protocol to the in-process agent_gateway() singleton. Flattens the request transcript into a UserTurn (the adapter protocol's text: str contract), submits via adapter.submit_turn(), and polls agent_state.last_report for completion. Registered at startup via ensure_default_registered().

Adapter Author Path

Hermes Agent, OpenClaw, or any other local/OpenAI-compatible agent can ship its own adapter by subclassing ConverseChannel and calling register_converse_channel() at startup. The active channel is swapped via set_active_converse_channel(name) (consumer API today; UI selector is Phase 5 Commit 4).
