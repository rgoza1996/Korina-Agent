Provider architecture

Hackathon refactor preview · 22 October 2026. Work is being reviewed on codex/hackathon-refactor, based on alpha. These changes are not yet merged into alpha or the release branch. Setup and rehearsal guide · Progress and verification evidence · Review PR #24.

GET /api/capabilities is the backend-owned registry for the response and agent roles. Response choices include llama.cpp, LM Studio, Ollama, and generic OpenAI-compatible endpoints. The agent registry separately exposes OpenAI-compatible and Anthropic-compatible APIs. The browser uses declared capabilities for URL editability and presets.

Settings and local lifecycle

Settings saves send observed field changes with explicit save revisions. A delayed initial read preserves drafts and newer confirmed saves; untouched HTML defaults are not posted as guessed settings. Provider activation waits for a loaded baseline, and failed initial reads retry from Settings.

Local activation and refresh consider response, multimodal STT, and enabled agent roles before stopping or restarting a service. Protected conflicts and missing prerequisites fail before teardown. Confirmed stops are distinguished from uncertain stop requests. Selection is saved before activation and is not automatically rolled back if activation fails.

Model-folder append/delete merges atomically with current settings. Removing the final folder preserves an explicit empty selection instead of restoring environment defaults.

Model discovery

Catalogs cover endpoint-loaded models, local GGUFs, LM Studio catalogs, and mmproj sidecars. IDs must be valid UTF-8 and fit 512 Unicode characters. Each role/source returns at most 512 IDs within 256 KiB of JSON-escaped identifiers; shared metadata covers at most 1024 IDs within 512 KiB. A selected ID found in a source survives truncation. Missing saved choices remain annotated with known incompatibility warnings.

Local discovery visits at most 10,000 entries per source. Manifest and LM Studio CLI data are capped at 2 MiB, with a 30-second CLI deadline. Request-scoped sidecar estimates have a separate 10,000-entry budget. Incomplete results and errors stay visible; activation admission is independent of display traversal limits.

Browser discovery bounds declared and streamed bodies at 8 MiB before parsing and preserves previous options/cache on malformed or oversized replies. Candidate agent discovery uses a bounded POST body without saving settings or activating a provider. Credentials inherit only when the actual normalized API base matches.

Transcription and speech

Buffered, partial, and SSE transcription share one multimodal capability-cache and Whisper fallback policy, including provider failures and no-speech handling. An empty selected model does not let a historical empty-key rejection cover every model on the endpoint. Whisper fallback keeps VAD filtering off to preserve quiet or clipped speech. Conversion and inference run away from the async event loop.

Compatible speech services must obey browser download, sample-rate, and duration budgets. Streamed playback finishes against the AudioContext clock: suspension cannot mark still-queued speech complete, and Stop remains usable. Closing the audio context before completion produces an error. See the playback implementation.

Optional acknowledgements

The ACK manifest has bounded, typed validation and unique normalized IDs. Invalid or missing catalogs leave startup and required voice readiness available. Health reports an explicit ACK error with unknown clip counts; ACK catalog/status/rebuild endpoints return HTTP 503 until the file is repaired. Invalid rebuilds preserve cached audio and queued work.

A voice change saves settings before requesting a rebuild. Failed saves request no rebuild. Browser requests coalesce pending choices and publish diagnostics only for their current voice/session; ACK status is separate from transcription status. A queued rebuild describes pending work, not ready audio. Server transactions serialize cache mutation even when an older browser request times out. Browser voice-change requests require the current saved voice; outdated requests fail before clearing audio.
