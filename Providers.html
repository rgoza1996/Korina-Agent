Provider architecture

Hackathon refactor preview · 22 October 2026. Work is being reviewed on codex/hackathon-refactor, based on alpha. These changes are not yet merged into alpha or the release branch. Setup and rehearsal guide · Progress and verification evidence · Review PR #24.

GET /api/capabilities is the backend-owned registry for the response and agent roles. Response choices include llama.cpp, LM Studio, Ollama, Meta Model API, and generic OpenAI-compatible endpoints. The agent registry exposes OpenAI-compatible, Meta Model API, and Anthropic-compatible APIs. The browser uses declared capabilities for URL editability, presets, and scoped credential defaults.

Meta Model API

The named meta profile is implemented for responses and independent built-in agent reports. It fixes the API base to https://api.meta.ai/v1 and starts no local Meta server. Its registry default is Bearer authentication from MODEL_API_KEY in the API process environment. An explicit response key-variable setting or direct agent key takes precedence. A generic/custom endpoint does not acquire that default from a Meta hostname; ordinary response-key inheritance still requires the same actual normalized API base.

Authenticated /models discovery supplies the model IDs; select one actually enabled for the team rather than assuming a hardcoded Meta model. Korina sends its existing Chat Completions payload to /chat/completions: model, supplied messages, temperature, max_tokens, and stream: false. The Meta response path omits the local/generic reasoning field, and neither response nor built-in report requests add reasoning_effort; reasoning stays at the model default.

Response token budget saves llm_max_tokens: 1–8192 tokens, default 180. Explicit chat max_tokens overrides it; an omitted value uses the saved setting. Agent reports keep their separate default of 512. Meta reasoning may consume the response budget before visible text. An empty answer ending with finish_reason: "length" produces an actionable error to increase the budget or choose another model, with no silent increase or retry.

For Meta/OpenAI-compatible agent reports, empty text with finish_reason: "length" appears through the existing last_error status and agent_error event while preserving the previous report. Adjust State report max tokens deliberately before submitting another turn; the same worker can recover without discarding that report. The default remains 512, with no automatic budget increase or retry. Intentional empty reports ending with stop stay suppressed, and visible truncated reports retain their existing behavior.

The focused demo keeps Whisper STT and Kokoro TTS local and uses Meta for one useful context-dependent answer with a fact retained in the current session. Existing history/report state does not establish durable memory or tool execution. This profile is pre-event preparation: record the actual kickoff SHA and later event additions in the event ledger.

Mocked profile tests do not establish authenticated live Meta access, useful presentation output, or prompt-cache hits. Rehearse the actual model and headset before presenting. See provider and credential contracts, the registry source, and the response payload.

Settings and local lifecycle

Settings saves send observed field changes with explicit save revisions. A delayed initial read preserves drafts and newer confirmed saves; untouched HTML defaults are not posted as guessed settings. Provider activation waits for a loaded baseline, and failed initial reads retry from Settings.

A successful save reconciles server-derived STT and agent fields into untouched controls, so a following role uses the confirmed response model on its next request. Newer edits, independent endpoints, explicit blank fields, and the last activated provider baseline remain intact. Cached URL editability and the selected probe entry update with those confirmed values; a save does not activate a provider.

Local activation and refresh consider response, multimodal STT, and enabled agent roles before stopping or restarting a service. Protected conflicts and missing prerequisites fail before teardown. Confirmed stops are distinguished from uncertain stop requests. Selection is saved before activation and is not automatically rolled back if activation fails.

Model-folder append/delete merges atomically with current settings. Removing the final folder preserves an explicit empty selection instead of restoring environment defaults.

Model discovery

Catalogs cover endpoint-loaded models, local GGUFs, LM Studio catalogs, and mmproj sidecars. IDs must be valid UTF-8 and fit 512 Unicode characters. Each role/source returns at most 512 IDs within 256 KiB of JSON-escaped identifiers; shared metadata covers at most 1024 IDs within 512 KiB. A selected ID found in a source survives truncation. Missing saved choices remain annotated with known incompatibility warnings.

Local discovery visits at most 10,000 entries per source. Manifest and LM Studio CLI data are capped at 2 MiB, with a 30-second CLI deadline. Request-scoped sidecar estimates have a separate 10,000-entry budget. Incomplete results and errors stay visible; activation admission is independent of display traversal limits.

Browser discovery bounds declared and streamed bodies at 8 MiB before parsing and preserves previous options/cache on malformed or oversized replies. Candidate agent discovery uses a bounded POST body without saving settings or activating a provider. Credentials inherit only when the actual normalized API base matches.

Audio-capability probes

The browser reads GET /api/audio-probe through a shared transport with a five-second deadline and a 16 MiB body limit. It validates at most 512 typed cache entries, including bounded keys and diagnostic fields. A failed, malformed, oversized, or superseded read preserves the known cache map; model discovery can continue with a visible warning. A newer discovery request aborts the old cache read.

Reset validates the selected triple and a successful DELETE /api/audio-probe response before removing the local entry. The reset control releases after that confirmation. Optional model discovery runs in the background and cannot keep a confirmed reset waiting.

POST /api/llm/probe-models keeps its 60-second batch budget and at most 15 seconds per candidate. Shared request ownership closes connected provider I/O when the client disconnects or the ASGI request is cancelled, then skips later candidates. Probe and STT fallback cache writes check ownership inside the configuration lock after reading current settings, so a retired lock waiter cannot publish a rejection or clear an entry. STT also checks ownership after a cache read before starting fallback.

Synthetic probe WAV paths are registered for cleanup before generation or writing; preparation failures remove incomplete files. These follow-ups have focused socket, cache-lock, and file-failure regressions. They do not establish remote compute cancellation; an active native inference step still drains before its resources are released.

Transcription and speech

Buffered, partial, and SSE transcription share one multimodal capability-cache and Whisper fallback policy, including provider failures and no-speech handling. An empty selected model does not let a historical empty-key rejection cover every model on the endpoint. Whisper fallback keeps VAD filtering off to preserve quiet or clipped speech. Conversion and inference run away from the async event loop.

Compatible speech services must obey browser download, sample-rate, and duration budgets. Streamed playback finishes against the AudioContext clock: suspension cannot mark still-queued speech complete, and Stop remains usable. Closing the audio context before completion produces an error. See the playback implementation.

Optional acknowledgements

The ACK manifest has bounded, typed validation and unique normalized IDs. Invalid or missing catalogs leave startup and required voice readiness available. Health reports an explicit ACK error with unknown clip counts; ACK catalog/status/rebuild endpoints return HTTP 503 until the file is repaired. Invalid rebuilds preserve cached audio and queued work.

A voice change saves settings before requesting a rebuild. Failed saves request no rebuild. Browser requests coalesce pending choices and publish diagnostics only for their current voice/session; ACK status is separate from transcription status. A queued rebuild describes pending work, not ready audio. Server transactions serialize cache mutation even when an older browser request times out. Browser voice-change requests require the current saved voice; outdated requests fail before clearing audio.

ACK bounds and recovery contract · Current architecture source · Setup and rehearsal

Health bounds loaded-model lists and distinguishes unavailable models from liveness. Malformed or unverified TTS health fails required readiness; a reachable lazy Kokoro still needs speech warm-up before a demo.

Frontend readiness uses a canonical contract of 28 required UI filenames, shared with the 30-file bundle, build, installed-wheel check, and disposable browser fixture. A missing, non-file, or unreadable required module makes /api/ready return HTTP 503 with frontend: false; /api/health remains HTTP 200. The optional ACK manifest and settings example are outside this required UI check. Custom file contents are allowed. This checks server file availability; browser execution and cache freshness require separate browser verification.
